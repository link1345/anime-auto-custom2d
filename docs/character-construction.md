# 2Dキャラクターモデルの構築

2.5Dのレイヤーメッシュを構成する仕組み。実在する奥行きのある身体全体や、任意のイラストから調整不要で完成するモデルを生成するものではない。

## 1. ローカル／Colabで推論

### ローカル

Python 3.12とGitを用意し、`scripts/setup_compute.ps1`を実行する。専用の`.venv-inference`にPyTorch CUDA、固定コミットのMoGe3、MediaPipeを導入する。推論用環境のPython絶対パスを、制作画面左の「ローカル推論の設定」に指定する。

今回の端末には専用環境を作成済み。既存See-through環境のCUDAパッケージを読み取り参照しているが、その環境のパッケージは変更していない。別端末ではセットアップスクリプトで独立導入する。

「MoGe3 深度を推定」または「人物・顔・関節を推定」を押す。処理は別プロセスで動き、編集画面を止めない。ログ、失敗、中止、完了を確認できる。「完了結果を取り込む」で、現在の原画とジョブ・ハッシュが一致する結果を反映する。入力を差し替えた古い結果は拒否する。

MoGe3の既定モデルは`Ruicheng/moge-3-vitl`。2026-09-26にHugging Face APIと実ダウンロードで存在を確認した。初回約1.48GB。固定モデルリビジョンは`184008f877d7ad1ad4c2cd2182a9bd1f63d0e5be`。既存の`.pt`パスも指定できる。MoGe2へ暗黙に切り替える処理はない。

深度は原画寸法を維持する。画像の縮小と、ネットワーク内部の解像度レベルは別物。レベル0〜9・精細化0〜10回を明示的に選択でき、既定は5・3。CUDAが標準。CPU対応は依存バックエンドによるため実測していない。

結果には深度、点群、有効領域マスク、カメラ内部パラメータ、推論環境と時間を保存する。無効画素はマスクで保持し、架空の深度に置き換えない。各パーツの頂点に有効な深度を反映し、メッシュのZとGLBに使う。保護したパーツは変更しない。

### Colab

1. `colab/Nagi_moge3.ipynb`または`colab/Nagi_mediapipe.ipynb`をGoogle Colabへアップロードする。画面から同じノートブックをダウンロードできる。
2. MoGe3はGPUランタイムを選ぶ。`USE_DRIVE=True`ならDriveへジョブ・ログ・結果を保存する。
3. `CHECKPOINT='Ruicheng/moge-3-vitl'`のままで公式重みを取得できる。手持ちの重みを使うときだけDriveのパスへ変更する。
4. 制作画面から該当ジョブZIPを出力し、ノートブックのアップロード欄で選ぶ。
5. 結果ZIPをダウンロードし、制作画面の「深度 / 人物推定の結果 ZIP」へ取り込む。

ノートブックは生成時のワーカーコードを埋め込む。ユーザーZIPに含まれるコードを実行しない。Colab自体での実行は未検証。

## 2. 人物・顔・関節を確認

MediaPipeのPose / Face / Hand Landmarkerを画像モードで使用する。関節ごとのvisibility/presenceが0.5未満、画面外、潰れた姿勢の候補は自動採用しない。人物マスクと顔・手のランドマークを保存する。

アニメで必ず成功するモデルではない。今回のNagiは顔478点を検出したが、胴体は肩幅などが極端に小さい誤検出だったため拒否した。手の21点検出も失敗した。**デモの胴体11関節は原画を見た手動配置**であり、自動推定成功の証拠にはしていない。

「関節を表示・クリックで配置」を有効にし、関節名を選んで画面をクリックするか、0〜1のx,yを入力する。Left/Rightは画面の左右。`root`は腰・胴の基準、`neck`は首の根元、`head`は頭の中心。手動位置はロックされ、推論再取り込みで保持される。

## 3. ボーン・腕を構成

上半身にはroot、neck、head、左右のshoulder/elbow/wrist/handの11点が必要。「ボーン・スキンを構築」で、階層と頂点ごと最大4本・合計1のウェイトを生成する。脚のhip/knee/ankleが揃えば脚ボーンも追加する。

頭の回転中心は首の根元。肩、肘、手首は独立したスライダーとWebSocketパラメータを持つ。GLBでも同じ骨階層・逆バインド行列を保存する。

腕パーツを選択し、保護を解除して「上腕・前腕・手へ分割」を押す。関節線分からの距離で画素を割り当てる。元パーツは非表示・保護して残し、子パーツの画素の和は元パーツを保つ。これは服の袖や隠れた肘の意味的補完ではない。境界と支点を確認する。

関節、役割、分割を変更するとリグは再構築が必要になる。古いリグのGLB出力を拒否する。

## 4. 表情の輪郭対応・モーフ

先に表情PNGを登録して配置矩形を指定する。基準にする顔または口等のパーツを選び、表情を選択して「フィット・モーフ生成」を押す。

- 自動対応はアルファ輪郭の周回順48点を使用する。全面不透明な画像は拒否する。
- 手動対応点は基準パーツ画像と表情画像、それぞれの画像内0〜1座標を同じ順序・個数で入力する。目・口等の内部点も追加できる。
- 距離重み付き補間で基準メッシュの頂点変位と表情画像UVを作る。三角形が反転する対応は採用しない。
- 表情強度0〜1で形状を補間し、同じ変形済みメッシュ上で表情テクスチャを合成する。輪郭を合わせずに画像を重ねるだけの経路とは区別する。

輪郭の自動対応は解剖学的な目・口の対応保証ではない。大きく異なる構図では手動点を使う。GLBに入るのは形状モーフであり、表情テクスチャのクロスフェードは制作アプリ側の機能。

## 5. 目・まつげ・瞳

See-throughの顔結果から白目・瞳・まつげが揃ったとき、白目と瞳のアルファの和集合から開口マスクを生成する。手動で「目レイヤーからマスク生成」も実行できる。顔ジョブは従来どおり2160以上の拡大顔を使う。

白目と瞳は元画像の画素・透明度を保持し、瞳自体を縦につぶさず開口で隠す。まつげは独立レイヤーとして閉眼方向へ変形する。星やハートは実際の瞳アルファ内に制限する。

元のSee-through切り抜きに誤りがあればマスクにも残る。閉眼の形は上下の開口補間で、専用の閉眼絵を自動生成するものではない。新しい目マスクは合成レイヤーで画素単位の検証を行ったが、新しいSee-through実推論による品質検証は行っていない。

## 6. 髪の衝突・隠れ部分

頭・左右肩に円形コライダーを置き、毛束の支点から先端までのサンプルが侵入した場合にばねの角度を制約する。初期から埋まっている部分は発散を避けて除外するため、最初の配置は修正が必要。全輪郭の厳密な接触や3Dの衝突判定ではない。

「隠れ境界を延長」は前面パーツの下に限り、元の境界色を1〜32px伝播する。元画素と元画像を保持し、Undoできる。生成補完や衣装の推測ではない。広い隠れ領域はSee-throughの生成レイヤーまたは描き足したPNGへ差し替える。

## 7. 出力・検証結果

「スキン・モーフ付き GLB」で、テクスチャ埋め込みのglTF 2.0を出力する。2.5D平面モデルなので、背面や横から見た実体積はない。髪の衝突、動的な目のマスク、表情テクスチャの合成はGLB標準へは保存せず、アプリの`.aac2d`モデルに保持する。

## 目のサイズを揃え、まばたきで隠す

1. 制作画面の右側「目の共通サイズ・まばたき」で「目の配置・変形を統一」を押す。表示中のまつげ・白目・瞳が、白目を基準とした共通配置・メッシュになる。左右に分割したレイヤーもまとめて処理する。明示的な統一操作は保護中の目パーツにも適用される。Undoで戻せる。
2. 「目の共通サイズ」で50〜150%に調整し、「共通サイズ・白目マスクを保存」を押す。各目の中心を保ち、3種類に同じ倍率を使う。この倍率とまばたきはNagiの描画処理に適用され、GLBには焼き込まれない。
3. 「まばたき確認」で「開く」「半分閉じる」「閉じる」を確認し、最後に「自動」へ戻す。確認設定は編集画面だけに適用され、配信・モデルには保存されない。

肌を下、白目、その上に瞳、最前面にまつげを配置する。白目の主要な輪郭から、瞳の穴を埋めた開口マスクを生成する。瞳がはみ出していても、そのはみ出しをマスクへ加えない。まばたきで開口範囲を狭め、白目・瞳を隠して下の肌を見せる。まつげは共通の閉じ位置へ圧縮する。肌そのものを前面に重ねて目全体を消す操作は不要。

肌には、See-through等で目の下まで補完された、目が描かれていない素材が必要。元の仮の頭・顔と分割前の目パーツは非表示にする。肌に元の目が残っている場合や目の下が透明な場合、このマスクだけでは補完できない。白目の輪郭自体が誤推定されている場合も元のマスク修正が必要。現時点の閉眼は上下から開口を狭める近似で、専用の閉じ目イラストを再現するものではない。


## ローカル推論でDLLのアクセス拒否が出る場合

`DLL load failed ... アクセスが拒否されました` は、推論モデルを読み込む前のライブラリ読み込みエラー。制限された環境から制作サーバーを起動すると、子プロセスの推論Pythonにも制限が引き継がれる場合がある。制作サーバーを停止し、このリポジトリで通常のPowerShellから `./start.ps1` を実行する。管理者権限は通常不要。通常起動でも再発する場合はDLLのアクセス権とセキュリティ製品の検出記録を確認する。

2026-09-26の該当環境では、制限下でNumPyのDLLアクセス拒否を再現し、通常のローカル起動でNumPy・PyTorch CUDA・MediaPipe・MoGe3の読み込み成功を確認した。NumPyの再インストールやモデル重みの再ダウンロードは不要だった。


## 顔全体の共通変形

Nagiの描画では、肌・眉・まつげ・白目・瞳・鼻・口・耳・髪を共通の親変形で動かす。各パーツの画像とメッシュは保持し、表情モーフ・まばたきマスクを先に処理してから同じ親変形を適用する。頬の赤みや瞳の装飾、未フィットの表情画像もこの親変形を共有する。

親変形は首位置を支点とする、小さな左右・上下の圧縮と移動、首の傾き。横向き時に各頂点のZを使って横ずらしする処理は廃止した。描画順のdepthと保存済みMoGe3形状は保持するが、顔の左右・上下移動量には使わない。リグが有効でも顔に頭ボーンの変形を二重適用しない。共通変形はアフィン変換のため、パーツごとに三角形の配置が違っても、同じ原画座標は同じ位置へ移動する。

髪は上部（目の高さまたはパーツ上半分まで）を固定し、毛先へ向けて滑らかに揺れを増やす。頭の親変形をその後に適用する。物理の有効・無効と既存の強さ設定は引き続き使用可能。

これは正面絵の一体感を保つ小さな動きで、横顔を新しく生成する処理ではない。大きな横向きでの輪郭・目・耳の回り込みには、別途方向差分や共通の非線形変形が必要。GLBにはこのNagi固有の描画処理は書き込まれない。パーツの表示状態は自動変更しないため、前髪を見せたい場合は前髪パーツの表示を有効にする。


## MoGe3共通立体顔面（追加）

右側の「共通立体顔面 / MoGe3」で「MoGe3から共通立体顔面を構築」を押す。取り込み済みのMoGe3 points.npyのカメラ深度とintrinsics.npyから49×73頂点の共通面を作る。既存パーツの画像・メッシュ・保護状態は保持する。凹凸の強さは0〜1.5で確認し、「立体顔面設定を保存」で保存する。チェックを外すと共通2D変形に戻る。構築・設定保存はUndo対象。

顔の全レイヤーと髪・装飾・まばたきは、正面での局所変形後に同じ面へ投影する。カメラの逆投影、首を支点とする3D回転、透視投影を行う。左右・上下は15度まで。ニュートラルでは元の画像座標へ戻る。メッシュ表示では共有面を表示する。

深度は共通座標で平滑化し、顔領域の中央値と推定幅に基づく上限で抑える。無効点は基準平面で補う。髪の下の顔、見えない横顔を復元するものではなく、推定値に髪の形状が混ざる可能性は残る。この旧モードは取り込み済みの全身画像の推論結果を使用する。顔専用画像の独立した推論と両視点での調整は、後述の「正面＋斜め / 共通顔面調整」を使う。顔の大きな横向きや自己遮蔽、裏面補完は対象外。

新しいMoGe3結果を取り込んだ場合は古い共有面を無効にするので再構築する。共有面はプロジェクトとNagiランタイム書き出しに保存される。GLB書き出しへの焼き込みは未対応で、従来の部品メッシュを書き出す。


## 斜め顔の作画対応

右側の「斜め顔の作画対応」で画面右・左の見本を登録できる。正方形画像をFFmpegで2160px以上に拡大し、原画像も別保存する。生成したNagiの画面右向き見本は `assets/directional/nagi-right-2160.png`。内蔵image_genを使用し、元の1254px画像をFFmpeg Lanczosで2160pxへ拡大した。生成プロンプトは同ディレクトリのPROVENANCE.md。角度18度は作画上の目安で、カメラ計測値ではない。

正面と斜め見本を並べ、選択した点を両方の画像上でクリックする。左右は画面基準。目の内外端・上下、鼻先、口両端、顎、両頬の14組を揃え「対応点から方向変形を保存」。初期対応点は人手による目測で `nagi-right-correspondence.json` に保存。自動検出したものではない。

対応点を薄板スプラインで共通49×73格子に変換し、正面〜指定角度の間を滑らかに補間する。反転する対応は保存を拒否する。頭・左右の＋が画面右向き、−が画面左向き。片側未登録の場合はその側の横向き変形を行わない。反転画像や未指定の形状は自動生成しない。有効時はこの方向対応をMoGe3共有面より優先し、上下・傾きは共通2D親変形を使用する。方向ごとの上下差分は対象外。

画像は形状の見本であり、画像全体のクロスフェードではない。既存の独立パーツ・まばたき・装飾を保持して共通面で変形する。新たに見える髪や耳、陰影の描き直し、方向別の閉眼イラストは別途必要。生成見本と完全一致するものではない。正面画像や顔の配置を変更した場合は対応点を再保存する。GLBへの方向変形の焼き込みは未対応。プロジェクトとNagiランタイムには方向画像と変形データを含めて保存する。

## 正面＋斜め / 共通顔面調整

現在は下記の「親子追従・形を保つ変形」を優先する構成も選べる。過去の推定結果は保持する。

右側の同名欄で、2160px以上の正方形の正面顔と斜め顔を個別にMoGe3推論する。各推論が完了するたびに左側の「完了結果を取り込む」を押す。顔深度は全身深度とは別に保存する。Colabでは同欄の正面・斜めジョブZIPを既存のMoGe3ノートブックでそれぞれ実行し、結果ZIPを取り込む。

下の作画対応で正面と斜めの14組の点を確認・保存したら、「② 両視点から共通顔面を調整・保存」を押す。両画像の独立したカメラ座標を対応点で位置合わせし、正面の画素配置を保つ奥行きを推定する。浅い共通面へ正則化した後、見本の目・鼻・口・頬・顎へ小さな作画補正を加える。補正量は顔画像幅の8%以内に制限し、途中角度も含めメッシュ反転を検査する。部品ごとに異なる深度移動は行わず、まばたき・装飾も同じ共通面を使う。

- 初期設定は「共通顔面の凹凸」0.35、「見本への作画補正」1。変更後は調整・保存ボタンで再構築する。
- 「複数視点で調整した顔面を使う」が有効なら旧MoGe3面・2D方向変形より優先する。凹凸は新しい欄で調整する。チェックを外すと従来モードに戻せる。
- 「方向確認」で正面・中間・見本の角度を確認する。基準角度18度は補間の終点指定であり、推定カメラ回転の実測値ではない。
- 今回は右斜めのみ登録。左向きは浅い正面深度による3D回転に戻り、左見本への作画調整は行わない。
- 顔深度や対応画像・点を更新した場合は再構築する。構築・有効化はUndo対象。

## 表情顔の抽出とまばたき・口パクのモーフ

「表情別の顔・部品抽出」で、正方形の顔画像、名前、必要部品を指定して登録する。小さい画像はFFmpeg拡大を有効にすると2160pxへ拡大される。原画を別保存し、正面の顔素材を置換しない。顔の配置が異なる場合は矩形を指定する。

登録した顔のジョブZIPを、最新版のSee-through Colabノートブックで実行する。モデル自体は全レイヤーを推論し、結果ZIPへ選択部品のみを格納する。結果ZIPを読み込んで候補を採用すると、表情ライブラリに部品別画像が追加される。通常パーツと目マスクは維持する。

次に元のまつげ／口パーツを選択し、「表情の輪郭対応・モーフ」で抽出した差分をフィットする。必要に応じて基準・目標の対応点を同じ順序で指定する。反転する対応は拒否する。完全な線への収縮は退化するため、厚みのある閉じまつげを使う。左右分割パーツでは各側に合った差分と対応点を使う。

フィット後、「モーフの動作」でまばたき／口パクを選び割り当てる。eyeOpenの逆数値（1-eyeOpen）、mouthOpenを強度として元の頂点を変形する。目の白目・瞳は既存の開口マスクを使い、カスタムまつげには従来の縦縮小を重ねない。口内の色・歯・舌は見本のテクスチャを補間表示する。音声からmouthOpenを生成する機能は含まない。曲線形状のまぶたマスクと完全閉眼専用の線切り替えは未対応。

実推論の品質とモーフの見た目は入力に依存する。合成テストの通過はGPU実推論や実画面の品質確認を意味しない。
